# Barber Bot — Telegram-бот записи к барберу

Реализация ТЗ v1.2 от 20.11.2026: онлайн-запись клиентов к барберу с
расписанием, услугами, уведомлениями и напоминаниями. Два режима —
«Админ» и «Клиент». Русский интерфейс, часовой пояс Europe/Moscow.

## Стек

| Компонент | Версия | Назначение |
|---|---|---|
| Python | 3.12 | диапазон aiogram — 3.11–3.15 |
| aiogram | 3.33.0 | каркас бота (Bot API 10.4) |
| aiosqlite | 0.22.1 | асинхронный доступ к SQLite (WAL) |
| APScheduler | 3.11.3 | напоминания 24/2/1 ч, анонимизация ПД, бэкапы |
| pydantic-settings | 2.16.3 | конфигурация из переменных окружения |

Архитектура: **один процесс** — long polling + планировщик + health-сервер
(aiohttp). Подробности: [docs/DATA_MODEL.md](docs/DATA_MODEL.md).
Ход разработки по фазам: [docs/phases/](docs/phases/).

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `BOT_TOKEN` | да | — | токен из @BotFather |
| `PRIMARY_ADMIN_ID` | да | — | Telegram ID основного админа |
| `BARBER_CONTACT_URL` | да | — | ссылка t.me/… для кнопки «Связаться с барбером» |
| `DATABASE_PATH` | нет | `data/barber.db` | путь к файлу SQLite |
| `BOOKING_HORIZON_DAYS` | нет | `30` | горизонт записи «на другую дату» |
| `PORT` | нет | `8080` | порт health-сервера (задаёт PaaS) |
| `BACKUP_REPO_URL` | нет | — | приватный GitHub-репозиторий бэкапов, `owner/repo` |
| `BACKUP_GH_TOKEN` | нет | — | GitHub-токен с правом Contents: write |
| `LOG_LEVEL` | нет | `INFO` | уровень логирования |

## Запуск локально

Быстрый путь — файл `.env`: скопируйте `.env.example`, впишите три значения
(токен, Telegram ID, ссылка на барбера) — они подхватятся при запуске
автоматически, приоритет остаётся у настоящих переменных окружения. Инструкция
для Windows и macOS/Linux — [docs/BOTFATHER.md](docs/BOTFATHER.md).

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt

export BOT_TOKEN="123456:ABC..."
export PRIMARY_ADMIN_ID="123456789"
export BARBER_CONTACT_URL="https://t.me/your_barber"

python -m bot.main
```

Проверка: `curl http://localhost:8080/health` → `{"status": "ok"}`.
Миграции применяются автоматически при старте.

Как получить `BOT_TOKEN` и свой Telegram ID — пошаговая инструкция:
[docs/BOTFATHER.md](docs/BOTFATHER.md). Быстрая проверка токена перед запуском:
`python check_bot.py` (getMe + снятие webhook).

## Развёртывание на Amvera (российский PaaS, автодеплой из GitHub)

Подробная пошаговая инструкция — `amvera-deploy-guide.pdf` (файл поставки
рядом с архивом). Кратко:

1. Код — в приватном репозитории GitHub (см. ниже).
2. **Проект**: [amvera.ru](https://amvera.ru) → регистрация по e-mail →
   страница **Баланс** → пополнение российской картой (Робокасса; ~300 ₽ ≈
   месяц тарифа «Начальный» 0,4 ₽/час) → «Создайте первый проект!» → тип
   **«Приложение»** → имя `barber-bot` → тариф **«Начальный»** (0,5 ГБ RAM;
   «Пробный» с его 0,1 ГБ боту впритык) → на шаге загрузки данных «Отмена».
3. **Переменные** (в разделе переменных и секретов): `BOT_TOKEN`,
   `PRIMARY_ADMIN_ID`, `BARBER_CONTACT_URL` и `DATABASE_PATH=/data/barber.db`
   — база в постоянном хранилище Amvera (3 реплики, переживает пересборки).
   Часовой пояс — переменная `TZ_NAME` (по умолчанию `Europe/Moscow`,
   менять не нужно).
4. **GitHub-интеграция**: вкладка **Репозиторий** → GitHub → fine-grained
   токен (доступ только к `barber-bot`, права — по подсказке Amvera:
   Contents и Webhooks, чтение и запись) → выбрать репозиторий и ветку
   `main` → «Применить». Каждый `git push` в `main` сам запускает сборку
   из корневого `Dockerfile` (файл `amvera.yaml` задаёт платформе среду
   docker — секция `meta` — и порт health-сервера 8080) и обновление бота;
   при сбоях вебхука — кнопка **Пулл**.
5. **Проверка**: статус «Приложение запущено» → `/start` в Telegram.

### Бэкапы SQLite (важно)

База хранится в `/data` — постоянном хранилище Amvera (3 реплики + бэкапы
платформы), поэтому переживает пересборки и обновления. Страховочный второй
контур: бот каждые 15 минут выгружает снапшот базы (`VACUUM INTO`) в
приватный GitHub-репозиторий, а при старте на чистом инстансе восстанавливает
базу из последней копии:

1. Создайте **приватный** репозиторий, например `owner/barber-bot-backup`.
2. Создайте fine-grained personal access token (права: Contents → Read and
   write только для этого репозитория).
3. Задайте `BACKUP_REPO_URL=owner/barber-bot-backup` и `BACKUP_GH_TOKEN=…`.

Без бэкапов бот работает — данные и так на постоянном хранилище; снапшоты —
вторая копия на случай форс-мажора.

## Другие варианты хостинга

- **SnapDeploy** — бесплатный контейнерный PaaS без карты: 4 контейнера,
  но 100 ч/мес и сон после 15 минут простоя (демо по требованию).
- **GitHub Codespaces** — 120 ядеро-часов/мес бесплатно (~60 ч на 2 ядрах):
  запуск по кнопке в браузере, работает пока Codespace открыт.
- **Render** — free-тариф (750 ч/мес, сон после 15 минут простоя,
  docs.render.com/docs/free). Карта по документации не нужна, но регистрация
  из России может не пройти проверку.
- **ClawCloud Run** — $5/мес кредитом за GitHub-аккаунт, но по опыту не
  открывается из России.
- **Hugging Face Spaces** — Docker-версия Spaces стала платной с июля 2026.
- **Локально** — `python -m bot.main` (см. «Запуск локально»).

## Структура проекта

```
bot/
├── main.py            # точка входа: polling + планировщик + health-сервер
├── config.py          # переменные окружения (pydantic-settings)
├── db/                # aiosqlite, миграции, репозитории (весь SQL здесь)
├── filters/           # IsAdmin / IsPrimaryAdmin
├── middlewares/       # регистрация пользователей
├── keyboards/         # клавиатуры и тексты кнопок
├── states/            # состояния FSM
├── handlers/
│   ├── client/        # меню, услуги, дата/время, корзина, «Мои записи»
│   └── admin/         # расписание, услуги, записи, ручная запись, админы
├── services/          # домен: слоты, записи, уведомления, напоминания, ПД, бэкапы
└── utils/             # даты MSK, телефон, шаблоны сообщений
tests/                 # 89 тестов (pytest + pytest-asyncio)
deploy/render.yaml     # конфигурация Render
docs/                  # инструкция админа, модель данных, чек-лист, отчёты фаз
```
