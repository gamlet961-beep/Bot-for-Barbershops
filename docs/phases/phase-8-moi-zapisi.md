# Фаза 8 — «Мои записи», отмена клиентом и ПД-цикл

> Отчёт по плану разработки (раздел 5.10). Статус: **завершена** 21.11.2026.

## Что сделано

- **`bot/handlers/client/mybookings.py`** — раздел «Мои записи» (п. 5.7 ТЗ):
  - активные и прошедшие записи за последние 2 месяца; отменённые скрыты;
    предстоящие — по возрастанию, прошедшие — по убыванию даты;
  - кнопка «Отменить запись» — только у записей с остатком ≥ 4 часов
    (окно считается на момент отрисовки И повторно при нажатии);
  - при остатке < 4 часов — «До визита меньше 4 часов. Для отмены свяжитесь
    с барбером» + кнопка связи (A.6.5);
  - отмена с подтверждением: уведомление админам, освобождение слота,
    подтверждение отмены клиенту (добавлен шаблон `client_cancel_self`,
    отправка из сервиса отмены), запись исчезает из списка.
- **`bot/handlers/client/contact.py`** — «Связаться с барбером»: inline-кнопка
  со ссылкой `BARBER_CONTACT_URL` (t.me/…), пересылка через бота не
  реализуется (п. 5.8 ТЗ).
- **`bot/services/privacy.py`** — ежедневная анонимизация (03:00 MSK, job в
  main.py): записи с датой визита старше 2 месяцев → имя «[анонимизировано]»,
  телефон NULL, флаг is_anonymized; дата/время/услуги/сумма сохраняются для
  статистики (A.8.2). Профили пользователей без записей в окне очищаются.
  Идемпотентна (повторный запуск ничего не меняет).
- Все 5 пунктов клиентского меню работают — заглушки фазы 1 полностью сняты.

## Зафиксированные решения

1. Граница анонимизации — календарная (дата слота строго раньше «сегодня − 2
   месяца»); окно отображения — та же дата включительно: расхождение на
   граничный день исключено.
2. Профиль пользователя (users.name/phone) очищается только при отсутствии
   записей в окне — активная история не должна «терять» клиента.
3. Подтверждение отмены клиенту отправляет единый сервис отмены — как и все
   прочие уведомления (одна точка правды).
