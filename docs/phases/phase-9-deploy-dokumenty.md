# Фаза 9 — Развёртывание, бэкапы и документация

> Отчёт по плану разработки (раздел 5.11). Статус: **завершена** 21.11.2026.

## Что сделано

### Сохранность данных на PaaS (B.9)

- **`bot/services/backup.py`** — `BackupService`:
  - снапшот живой базы `VACUUM INTO` (консистентен при WAL);
  - выгрузка в приватный GitHub-репозиторий через Contents API (создание/
    обновление по sha), каждые 15 минут (job APScheduler);
  - при старте на чистом инстансе: база пуста и есть удалённый бэкап →
    автоматическое восстановление, затем повторные миграции;
  - транспорт GitHub изолирован в переопределяемых методах — тесты идут
    без сети.
- **main.py**: восстановление при старте (до инициализации админа) + job
  бэкапа каждые 15 минут (только при заданных BACKUP_REPO_URL/BACKUP_GH_TOKEN).

### Конфигурация развёртывания

- **`Dockerfile`** перенесён в корень (требование Render и HF Spaces);
- **`deploy/render.yaml`**: web-сервис, docker-рантайм, бесплатный тариф,
  health-check `/health`, секретные переменные через панель, autoDeploy;
  в комментарии — инструкция keep-alive пинга (сон бесплатного инстанса
  через 15 минут без трафика).

### Комплект документации (раздел 12 ТЗ)

- **`README.md`** — стек, переменные окружения, запуск локально, тесты,
  развёртывание на Render по render.yaml, keep-alive, настройка бэкапов
  (приватный репозиторий + fine-grained токен), резервный вариант
  Hugging Face Spaces, структура проекта (B.12);
- **`docs/ADMIN_GUIDE.md`** — инструкция администратора: первый вход,
  расписание (шаблоны, исключения, блокировки, отмена дня), услуги,
  записи (фильтры, поиск, отмена, ручная запись), управление вторым
  админом, что видит клиент, таблица уведомлений (B.11);
- **`docs/DATA_MODEL.md`** — итоговая схема БД, отличия от предварительной
  модели ТЗ с обоснованиями, архитектурная схема, жизненный цикл записи;
- **`docs/CHECKLIST.md`** — чек-лист приёмки: все 81 критерий акта с
  конкретными шагами проверки и отметками автотестов;
- **`docs/akt-priemki-status.md`** — сводный статус по акту: 76/81 закрыты
  кодом и тестами, 4 требуют живого окружения (B.1, B.7, B.11, B.12),
  1 требует передачи доступов заказчиком (B.10); перечень остаточных
  шагов до подписания акта;
- отчёты по фазам 0–9 в `docs/phases/`.

## Зафиксированные решения

1. Бэкап — GitHub Contents API: бесплатно, приватно, версионируемо; формат
   одного файла `backups/barber.db` (последний снапшот поверх предыдущего).
2. Восстановление выполняется только на файловой базе и только при пустой
   таблице bookings — случайно не перезапишет живые данные.
3. Dockerfile в корне репозитория: одинаково подхватывается Render и
   Hugging Face Spaces, deploy/render.yaml хранит только настройки Render.
