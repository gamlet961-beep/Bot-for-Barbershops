# Фаза 6 — Раздел «Записи» и ручное создание записи

> Отчёт по плану разработки (раздел 5.8). Статус: **завершена** 21.11.2026.

## Что сделано

### Раздел «Записи» (п. 4.4 ТЗ) — `bot/handlers/admin/bookings.py`

- **Фильтры**: сегодня (открывается по кнопке меню), завтра, конкретная дата,
  диапазон дат (две даты, с проверкой порядка), все предстоящие (в пределах
  горизонта), поиск по имени/телефону. Отменённые записи в списки не попадают;
  прошедшие помечаются «· прошла».
- **Список**: строка на запись — день недели, дата, время, имя, телефон,
  услуги, сумма; сортировка по дате и времени (п. 4.4 ТЗ); при больше 20 —
  подсказка уточнить фильтр.
- **Детали записи**: клиент, дата и день недели, время, услуги с ценами,
  сумма, кто создал (клиент/администратор), согласие на ПД, статус.
- **Отмена записи** с подтверждением: клиенту уведомление, слот освобождается
  (сервис фазы 3), фиксация причины и инициатора.
- В меню раздела — вход в ручное создание записи.

### Ручное создание записи (п. 4.5 ТЗ) — `bot/handlers/admin/manual.py`

- Полный путь: услуги (toggle-мультивыбор) → дата (неделя / другая дата в
  пределах горизонта) → свободный слот → имя → телефон (валидация) → сводка
  с явной пометкой «Мгновенные уведомления отправляться не будут» → создание.
- `created_by='admin'`: ни подтверждения клиенту, ни уведомления админам
  (п. 4.5 ТЗ, A.4.6); напоминание админу за 1 час планируется сервисом
  штатно (A.4.7).
- Телефон сверяется со справочником users: при совпадении запись привязывается
  к аккаунту клиента — планируются и напоминания клиенту за 24/2 ч (примечание
  п. 7.1 ТЗ).

Кнопка «Записи» в меню админа открывает раздел (последняя заглушка фазы 1
снята; все разделы админ-меню работают).

## Результат фазы

Рабочее место администратора по записям готово полностью; ручная запись
создаётся без единого мгновенного уведомления, но с плановым напоминанием.

## Зафиксированные решения

1. Поиск — только по активным записям (отменённые не интересуют администратора;
   история остаётся в БД для статистики).
2. Ручная запись без совпадения по телефону хранит только снимки имени и
   телефона (client_id = NULL) — клиентские напоминания создаются сразу со
   статусом skipped.
3. Согласие на ПД (pd_consent_at) для ручных записей не фиксируется: клиент
   не взаимодействовал с ботом (см. docs/DATA_MODEL.md).
