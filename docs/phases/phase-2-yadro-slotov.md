# Фаза 2 — Ядро расписания и слотов

> Отчёт по плану разработки (раздел 5.4). Статус: **завершена** 21.11.2026.

## Что сделано

- **`bot/services/scheduling.py`** — вся логика слотов чистыми функциями без
  зависимости от aiogram:
  - `validate_interval` — правило кратности 2 часам (п. 4.2 ТЗ): длительность
    обязана быть кратна двум часам, конец позже начала; интервалы через
    полночь не поддерживаются (для барбершопа не нужны, зафиксировано);
  - `generate_slots` — нарезка от времени начала шагом 2 часа, неполный
    последний слот отбрасывается (защита от рассинхронизации, п. 4.2 ТЗ);
  - `resolve_working_day` — каскад «исключение на дату → шаблон дня недели →
    выходной» (гибридная модель ТЗ);
  - `available_slots` — сетка минус активные записи минус блокировки минус
    уже начавшиеся слоты (граница — момент начала слота);
  - `within_horizon` — горизонт записи `BOOKING_HORIZON_DAYS` (по умолчанию 30,
    допущение № 1 плана);
  - `can_cancel` — окно отмены ≥ 4 часов до визита (п. 5.7 ТЗ);
  - `my_bookings_window_start` — окно «Мои записи» 2 месяца (п. 5.7, 9.2 ТЗ);
  - `split_for_display` — предстоящие по возрастанию, прошедшие по убыванию;
  - `parse_hours_range` появится в фазе 3 (ввод часов администратором).
- **Тексты ТЗ** зафиксированы константами: INTERVAL_ERROR_TEXT (дословно из
  п. 4.2), NO_SLOTS_TEXT, SLOT_TAKEN_TEXT, CANCEL_TOO_LATE_TEXT.
- **Телефон** (`bot/utils/phone.py`, подготовлен в фазе 0): `+7…/8…/9…` и
  разделители → нормализация к `+7XXXXXXXXXX`.

## Зафиксированные решения

1. «Прошедший» слот определяется по моменту начала (слот, начавшийся сейчас,
   бронировать нельзя).
2. День без шаблона и без исключения — выходной (в ТЗ явно не задано;
   безопасная трактовка: не работаем, пока админ не задал часы).
3. Интервалы через полночь не поддерживаются — `validate_interval` их
   отклоняет (барбершоп работает в пределах суток).
