# Фаза 1 — Роли и главные меню

> Отчёт по плану разработки (раздел 5.3). Статус: **завершена** 21.11.2026.

## Что сделано

- **Репозитории** `bot/db/repositories/`:
  - `users.py` — upsert по telegram_id (middleware), связка имени и телефона
    при оформлении записи, поиск по телефону (для ручных записей, фаза 6);
  - `admins.py` — whitelist: `ensure_primary` (инициализация при старте,
    защита от второго основного), `is_admin` / `is_primary`, добавление и
    удаление второго админа, список админов, tg-id для рассылки уведомлений.
- **Фильтры** `bot/filters/is_admin.py`: `IsAdmin` / `IsPrimaryAdmin` — работают
  и для сообщений, и для callback-запросов; база приходит из workflow-данных.
- **Middleware** `bot/middlewares/register_user.py`: регистрация/обновление
  пользователя при каждом входящем событии (A.1.5 — связка telegram_id + phone
  начинается здесь).
- **Клавиатуры** `bot/keyboards/`:
  - клиентское меню — ровно 5 пунктов ТЗ (Услуга, Дата и время, К записи,
    Мои записи, Связаться с барбером), reply-клавиатура;
  - меню админа — 4 раздела; «Управление админами» показывается только
    основному админу (A.1.4).
- **Обработчики**:
  - `/start` различает роли: админ получает меню админа, клиент — клиентское
    меню с приветствием;
  - `bot/handlers/admin/admins.py` — управление админами: просмотр списка,
    добавление и удаление второго админа по Telegram ID с валидацией ввода
    (целое число, дубликаты, защита основного, отмена — /menu);
  - кнопки разделов-заглушек честно сообщают, в какой фазе заработают
    (промежуточное состояние, прод — только после фазы 9).
- **main.py**: инициализация основного админа из `PRIMARY_ADMIN_ID`,
  подключение middleware регистрации.

## Результат фазы

Роли разграничены: админ — по whitelist из БД, посторонний не попадает в
админские обработчики (роутер закрыт фильтром `IsAdmin` целиком).
Основной админ управляет вторым; второй видит все разделы, кроме
«Управление админами».

## Зафиксированные решения

1. Роль админа определяется только таблицей `admins` (единственный источник
   правды); отдельного поля role в users нет — модель ТЗ упрощена без потери
   функциональности (задокументировано в docs/DATA_MODEL.md, фаза 9).
2. Добавляемый админ не обязан сначала написать боту: строка users создаётся
   при добавлении.
3. Отмена диалогов администратора — командой /menu (сброс FSM), как принято
   в RU-ботах.
