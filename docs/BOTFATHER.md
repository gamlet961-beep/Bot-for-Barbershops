# Создание тестового бота через @BotFather

Бот в Telegram создаётся только из личного аккаунта владельца — через
официального бота [@BotFather](https://t.me/BotFather). Разработчик (и тем более
скрипт) сделать это за вас не может: вход в ваш Telegram защищён телефоном и
кодом подтверждения. Ниже — вся последовательность для тестовой сборки: два
обязательных значения, которые нужно получить (токен и ваш Telegram ID), и
запуск проекта с ними.

## Шаг 1. Создание бота (≈1 минута)

1. Откройте в Telegram чат [@BotFather](https://t.me/BotFather) → кнопка **Start** (или отправьте `/start`).
2. Отправьте команду `/newbot`.
3. **Name** — отображаемое имя, кириллица допустима. Для теста: `Барбер (тест)`.
4. **Username** — латиницей, обязан оканчиваться на `bot` и быть уникальным.
   Для теста: `barber_test_demo_bot` (если занят — добавьте свой ник:
   `barber_test_ivan_bot`).
5. BotFather пришлёт сообщение с токеном вида `1234567890:AAEhBOweik6ad9r_QXMENQjcrGbqCr5G-p0`.
   **Скопируйте и сохраните его** — это единственный раз, когда он показывается так удобно (потом доступен через `/mybots` → ваш бот → **API Token**).

Токен — это полный доступ к боту. Не публикуйте его в чатах, репозиториях и
скриншотах. Если утёк — отправьте BotFather `/revoke`, получите новый и
замените в переменных окружения.

## Шаг 2. Обязательные настройки в BotFather (≈1 минута)

**Список команд** (кнопка меню рядом с полем ввода):

```
/setcommands
```
→ выбрать своего бота → вставить:

```
start - Запустить бота и открыть меню
menu - Открыть главное меню
```

**Описание** (показывается в пустом чате с ботом до первого сообщения):

```
/setdescription
```
→ выбрать бота → вставить: `Тестовая сборка барбер-бота: запись клиентов, расписание, услуги, напоминания. Для приёмочных испытаний.`

**О боте** (строка в профиле бота):

```
/setabouttext
```
→ выбрать бота → вставить: `Барбер-бот — запись к мастеру в Telegram. Тестовый контур.`

Автоматически устанавливать команды из кода не нужно — проект не использует
`set_my_commands`, меню задаётся вручную один раз.

## Шаг 3. Ваш Telegram ID

Бот различает владельца-админа по числовому Telegram ID (переменная
`PRIMARY_ADMIN_ID`). Узнать свой ID:

1. Откройте [@userinfobot](https://t.me/userinfobot) → **Start**.
2. Бот ответит сообщением вида `Id: 123456789` — это и есть ваше число.

## Шаг 4. Запуск на своём компьютере

### 4.1. Что понадобится

- Python 3.10–3.13: [python.org/downloads](https://www.python.org/downloads/).
  На Windows при установке отметьте галку **Add python.exe to PATH**.
  Проверка: `python --version`.
- Проект: распакуйте `barber-bot.zip` в любую папку, например `C:\barber-bot`
  (Windows) или `~/barber-bot` (macOS/Linux).
- Три значения из шагов 1–3: токен, ваш Telegram ID, ссылка на барбера.

### 4.2. Настройка `.env` (один раз)

В корне проекта скопируйте `.env.example` в `.env` и впишите свои значения:

```dotenv
BOT_TOKEN=1234567890:AAE...ваш_токен
PRIMARY_ADMIN_ID=123456789
BARBER_CONTACT_URL=https://t.me/your_barber
```

`.env` подхватывается при запуске автоматически; если та же переменная задана
в окружении — приоритет у окружения (так работает Render). Файл уже добавлен
в `.gitignore` — в репозиторий и архив поставки он не попадает.

### 4.3. Установка зависимостей и запуск

Windows (PowerShell):

```powershell
cd C:\barber-bot
py -m venv venv
venv\Scripts\Activate.ps1
pip install -r requirements.txt
python check_bot.py      # проверка токена: getMe + снятие webhook
python -m bot.main       # long polling + планировщик + health
```

Если PowerShell запрещает запуск скриптов (`running scripts is disabled`),
выполните один раз `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
или используйте классический `cmd` с активацией `venv\Scripts\activate.bat`.

macOS / Linux:

```bash
cd ~/barber-bot
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python check_bot.py      # проверка токена: getMe + снятие webhook
python -m bot.main       # long polling + планировщик + health
```

`check_bot.py` проверяет токен (`getMe`) и снимает webhook (`deleteWebhook`) —
иначе, если токен раньше использовался с webhook, long polling не получал бы
обновлений. Токен скрипт возьмёт из `.env`, окружения или аргумента.

Бот жив, если в браузере по адресу `http://localhost:8080/health` отвечает
`{"status": "ok"}`. Остановка — `Ctrl+C` в окне терминала.

### 4.4. Важно при переносе с песочницы

- **Один токен — один работающий бот.** Если бот уже запущен где-то ещё
  (песочница, другой компьютер, Render), второй экземпляр увидит в логах
  `409 Conflict: terminated by other getUpdates request` и не будет получать
  сообщения. Остановите первый экземпляр.
- **Локальная база стартует пустой**: тестовые записи из песочницы не
  переносятся (в архив база не включена намеренно). Создайте заново шаблон
  недели и услуги — 2 минуты по [ADMIN_GUIDE.md](ADMIN_GUIDE.md).
- Файл базы — `data/barber.db`; чтобы сбросить тестовые данные, достаточно
  удалить его при остановленном боте.

## Шаг 5. Дымовой тест в Telegram (2 минуты)

1. Найдите своего бота по username → **Start** → команда `/start`.
   Ответ: приветствие и главное меню клиента.
2. Пройдите мини-сценарий: «Записаться» → услуга → мастер → слот → подтверждение.
3. Отправьте `/admin` **с аккаунта владельца** (тот, чей ID в `PRIMARY_ADMIN_ID`) —
   должна открыться панель администратора. С другого аккаунта `/admin` отвечает отказом.
4. Полный регламент — [CHECKLIST.md](CHECKLIST.md), 81 критерий акта приёмки.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `check_bot.py`: «токен неверен или отозван» | Опечатка при копировании или токен отозван через `/revoke`. Скопируйте заново: `/mybots` → бот → API Token. |
| Бот молчит, хотя процесс запущен | У этого токена установлен webhook. Запустите `python check_bot.py` — он снимет webhook. |
| В логах `Conflict: terminated by other getUpdates request` | Токен уже используется другим запущенным процессом (например, инстанс на Render). Остановите второй процесс — у одного токена может быть только один потребитель. |
| `RuntimeError: Не заданы обязательные переменные…` | Нет заполненного `.env` в корне проекта (или бот запущен из другой папки). Заполните `.env` по шагу 4.2 и запускайте из корня проекта. |
| `PRIMARY_ADMIN_ID` указан, но `/admin` отвечает отказом | ID взят неверно (перепутаны с номером телефона или username). Перепроверьте через @userinfobot тем же аккаунтом, с которого пишете боту. |
